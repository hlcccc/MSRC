# 快速版测试流程说明

## 这版怎么测

先用我方交付的全量逐样本原始证据，重新计算三个指标；再由测试方在自己的服务器上，使用官方模型对固定小样本重新推理，检查回答、信号融合和多层内容安全预警能否实际运行。两个环节分别保存证据，最后合并生成总报告。测试方不重新训练基础模型，也不重新拟合校准器或预警参数。

这里的全量复核不是打开我方已经做好的结果表。程序会核验逐样本记录、固定划分和参数，重新计算信号、融合输出、校准提升及预警准确率，并与原始记录逐项核对。但模型的大规模回答生成是在历史实验中完成的，本次没有重新生成全量回答。

## 依次做什么

1. 下载独立快速分支的代码，以及本版证据压缩包。代码可以从GitHub取得，也可以解压网盘中的代码ZIP；不是依赖我方服务器上的脚本。
2. 运行环境安装和证据复核脚本。程序校验压缩包、恢复材料，在CPU上重新计算三个指标，生成HTML、MD和逐样本数值文件。
3. 安装GPU推理环境，下载并核验与原版一致的官方模型。离线使用时，由我方另行提供原样复制的完整models和env目录，用《交付说明》中的离线命令替代联网安装和下载。
4. 运行现场抽测。POPE和TextVQA各固定抽3题，三个模型分别重新生成回答，共18条模型记录；内容安全四类来源各抽2题，共8题，重新生成并运行多层预警。抽测不读取历史回答作为本次输出，也不重新拟合。
5. 生成总报告。只有全量复核数值达标、现场抽测完成并通过程序检查，且测试方确认采用这种方式，才生成快速测评通过结论。

## 三个指标分别测什么

| 指标 | 全量证据复核 | 现场新推理检查 |
| --- | --- | --- |
| 1.11 不确定性量化建模 | 从六组全量证据重建信号使用明细，检查同一次融合实际参与的不同信号不少于3种；不可用或未参与的信号不计入 | 检查新回答的信号提取、参与状态、融合权重和置信度输出 |
| 1.12 不确定性来源分析 | 使用原固定开发/测试划分及开发侧已拟合参数，重算三个模型、两数据集的测试集ECE及相对提升；六组分别不低于10%，平均值只作展示 | 用相同已拟合参数处理新采集信号，展示融合结果；不以18条抽测结果代替全量校准性能 |
| 1.13 多模态生成内容风险评估 | 核查6,720条数据的角色划分、3,360条测试请求及对应历史逐token预警记录、答案核验记录，重算总体准确率和混淆矩阵；总体准确率不低于75% | 对8条请求重新生成，检查多层预警、输出缓冲和触发预警后的停止行为；不是重新验证全量准确率 |

事实性证据覆盖三个模型分别在POPE 9,000条、TextVQA 5,000条上的采集，共42,000条模型记录。计算校准指标时，仅评价原划分的测试部分：每个模型POPE 4,500条、TextVQA 2,496条；开发部分不混入测试指标。

现场安全抽测不重新调用答案验证模型判完整基准准确率；全量复核读取并核查历史答案验证记录，也不重新提取全量隐藏状态或复核原始图像上的全部模型前向。历史时间戳只证明历史本地缓冲记录的顺序，不证明当前服务器对外HTTP输出的时间。

## 与之前无需训练版的区别

| 项目 | 原无需训练版 | 独立快速版 |
| --- | --- | --- |
| 基础模型训练 | 不训练 | 不训练 |
| 校准器、检测头及阈值 | 加载我方已经训练或拟合好的参数 | 同样加载已经训练或拟合好的参数 |
| 事实性推理 | 三个模型重新处理POPE和TextVQA全量，共42,000条模型记录 | 读取全量历史原始证据重新计算；现场新推理18条模型记录 |
| 内容安全推理 | 重新完成测试侧全量生成、多层预警及答案核验 | 复核全量历史记录；现场新推理8条请求 |
| 指标定义与门槛 | 信号数、校准性能提升、预警准确率，分别按既定标准判定 | 定义与门槛不变；改变的是哪些推理在本次执行、哪些证据由我方提前提供 |
| 验证范围 | 检验全量重新推理流程是否可执行及新结果是否达标 | 检验全量历史证据能否独立复算，同时检查现场小样本功能是否可运行 |
| 耗时主要花在哪里 | 全量多次模型推理及安全核验 | 材料和模型传输、安装、模型加载、少量现场推理；CPU复核本身较快 |

因此，快速版不是只交一张结果表，也不是全量重新推理的等价替代。若原验收方案明确要求测试方现场重新生成全量回答，必须先取得测试方对变更测评方式的认可，或继续执行原无需训练版。

## 结果在哪里

全量复核报告目录：runs/fast_001/review/。指标1.11看signal_report.html或signal_report.md；指标1.12看calibration_report.html或calibration_report.md；指标1.13看warning_report.html或warning_report.md。该目录还保存summary.json和samples/逐样本明细。

现场抽测报告：runs/fast_001/demo/demo_report.md。新回答和融合明细在factual/demo_results.json，新内容安全记录在safety/sample_01.json至sample_08.json，均位于demo目录内。

最终总报告：runs/fast_001/report.html、runs/fast_001/report.md。HTML可以直接打开；MD是可直接查看的文字及数值输出。

## 当前验证状态

独立新环境中的完整CPU证据复核已通过，核验及复核约17秒，不包括文件传输、GPU环境安装、模型下载与现场推理。历史证据复核得到六组平均校准提升56.90%、各组最少实际参与信号6种、内容安全总体准确率97.62%。这些是历史全量证据重算的结果，不是本轮新GPU全量推理结果。

新现场GPU抽测驱动尚未完整实跑，快速版网盘新目录尚未确认上传和生成分享链接。因此目前不能说快速版全流程已验证完成，也不能承诺含下载和现场抽测在几小时内完成。
