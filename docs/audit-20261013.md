# 达标表的合规审计（2026-10-13）

用户要求：核对 POPE / TextVQA / CHAIR 三列 × 三个模型的实验流程与数据是否合规。
这里记录查了什么、查到什么、以及**没查到的不能算数**。

审计工具（都在仓库里，可复跑）：

    python scripts/pipeline_audit.py --cell "MODEL|DATASET=PATH@官方条数"   # 单格内部
    python scripts/audit_acceptance.py --manifest runs/cells.json          # 跨格公平性
    python scripts/audit_generation_budget.py --cell ... --tokenizer ...   # 生成长度一致性

---

## 一、结论先说

**9 个达标格里 8 个通过全部检查；Qwen2.5-VL-7B × CHAIR 不通过。**

具体问题：`cell_Qwen2.5-VL-7B_chair.jsonl` 的 1,200 条答案是**两批不同生成长度上限拼起来的**
——460 条卡在 64 tokens，740 条卡在 128 tokens。因此它**不能与另外两格直接比较**，
Qwen 的 3/3 在这个格子重采之前**不成立**。

## 二、查了什么，结果如何

### 2.1 跨格公平性（`audit_acceptance.py`）

| 检查项 | POPE | TextVQA | CHAIR |
|---|---|---|---|
| 三个模型的**条目集合完全相同** | ✓ 9,000 | ✓ 5,000 | ✓ 1,200 |
| 三个模型的**图片集合完全相同** | ✓ | ✓ | ✓ |
| 证据通道可用率一致（views / resamples / verifications / cross_model / ocr） | ✓ | ✓ | ✓ |
| 按真实图片身份切分，两半无共用图 | ✓ | ✓ | ✓ |
| 独立复算的准确率与总表一致 | ✓ | ✓ | ✓ |
| 14 个划分种子全部达标 | ✓ 3/3 格 | ✓ 3/3 格 | Qwen 14/14；另两格本就未达 |

POPE 补充：9,000 条 = 三个官方 setting 各 3,000 题；1,500 个图片文件名但**只有 500 个 COCO 图身份**
（每张图被问 18 次），切分按 COCO id 分组，跨半区共用组 **0**。

### 2.2 标签来源（最硬的一层：不查元数据，直接重推）

拿原始答案 + 官方答案把标签重新推一遍，逐条比对：

| 格 | 可重推 | 逐条吻合 |
|---|---|---|
| POPE ×3 | 9,000/9,000 | **100%** |
| TextVQA ×3 | 5,000/5,000 | **100%** |
| CHAIR ×3 | 不能由答案单独重推（依赖 COCO 标注） | 每行都写着规则 `chair-s: any object mentioned that COCO does not annotate` |

补充：`pope_official` 解析与宽松解析的差异只有 0.2%（LLaVA 0%），且**存的标签与声明的官方解析完全一致**。

### 2.3 生成长度一致性（这一项抓到了问题）

答案被生成预算截断时，token 数会**正好等于**那个预算，所以 token 数会在整数上堆积。

| 格 | 卡在 64 | 卡在 128 | 判定 |
|---|---|---|---|
| LLaVA × CHAIR | 1.0% | 740 条 | 单一上限 ✓ |
| **Qwen × CHAIR** | **37.5%（460 条）** | 740 条 | **混了两批上限 ✗** |
| InternVL × CHAIR | 0.0% | 740 条 | 单一上限 ✓ |
| 三格的 POPE / TextVQA | ≤2.4% | — | 短答，上限不构成影响 |

**为什么这要紧**：CHAIR 的标签是"描述点到了 COCO 没标注的物体"，**描述越长越容易点到**。实测：

| 那 1,200 条里的两批 | 条数 | 中位长度 | **幻觉率** |
|---|---|---|---|
| 64-token 那批 | 460 | 54 词 | **9.1%** |
| 128-token 那批 | 740 | 103 词 | **19.9%** |

混在一起使整格幻觉率降到 15.8%、"从不预警"升到 84.8% —— 而 85% 正是结题线。
**这不是方法在这格更灵，是这一格的描述更短。**

（成因：`collect_evidence.py` 的默认 `max_new_tokens` 是 64；早先那批没带 `--max-new-tokens 128`，
后来 A9 队列续跑时才补上，而**断点续采按条目 key 跳过已采条目**，那 460 条短答案就留在文件里。
条数、标签分布、通道可用率全都正常，只有 token 数看得出来。）

#### 预算影响的配对测量（同条目、只换预算）

上面 9.1% 对 19.9% 是**不同条目**之间的比较，可能被条目本身的难易混淆。干净的测法是固定条目：
把云端 128-token 重采的答案按 `chair-s` 规则重新打标签，在同一批 460 个 id 上与原来 64-token 的比。

| 同样这 460 条，只换生成预算 | 标记为幻觉 | 幻觉率 |
|---|---|---|
| 64 tokens | 42 | **9.1%** |
| 128 tokens | 98 | **21.3%** |
| 差 | +56 | **+12.2 个百分点** |

**逐条翻转：判安全→幻觉 56 条，幻觉→判安全 0 条。** 单方向、不可逆 —— 这正是机理决定的：
描述越长，点到的物体越多，点到"COCO 没标注的物体"的机会只增不减。

因此这一格的 15.8% 幻觉率、84.8% 的"从不预警"，是**预算偏短**带来的，不是 Qwen 在这格更准。
若全部按 128 tokens：阳性率约 `740×19.9% + 460×21.3% ≈ 20.4%`，"从不预警"降到约 **79.6%**。

### 2.4 旁证（独立于上面的检查）

- LLaVA × CHAIR 的原机答案与云端用 128 tokens 的重采**逐字 1,200/1,200 完全相同** → 该格确为 128。
- Qwen × CHAIR 只有 740 条相同，460 条是重采的**前缀** → 与 64-token 的推断互相印证。

## 三、对结论的影响

- **Qwen × CHAIR 87.2% 暂不采信**，3/3 的说法在重采完成前不成立。
- 另外 8 格（POPE ×3、TextVQA ×3、CHAIR 的 LLaVA 与 InternVL）通过本次全部检查。
- 需要注意但不构成违规的三条，报告里要写明：
  1. **InternVL × POPE 只比"从不预警"高 0.98 个点**（90.47% → 91.44%），达标主要来自基率；
  2. **Qwen × CHAIR 在修好之后可能不再达标**——按长描述那批的 19.9% 幻觉率外推，
     "从不预警"会落在 80% 附近，需要方法贡献 5 个点以上，而 CHAIR 上实测的方法贡献是 3~4 个点；
  3. 三格的 CHAIR 都补进了另外两个模型的描述（`add_cross_model_reading.py`），三格**同等处理**，
     但这是一次跨模型集成，报告里必须写明。

## 三之二、按主流评测规范看，这一格算不算合规

**主流做法。** 生成预算（`max_new_tokens`）在主流评测里是**基准任务配置的一部分，不是每个模型各自的选择**：
lmms-eval 这类标准评测框架把 `max_new_tokens` 写在任务配置里，所有模型在同一份配置下跑
（[LMMs-Eval, NAACL 2025 Findings](https://aclanthology.org/2025.findings-naacl.51.pdf)；
[EvalScope 的 POPE 说明](https://evalscope.readthedocs.io/en/v1.5.2/benchmarks/pope.html)）。
论文把解码设置写在 Implementation Details 里、对所有模型统一适用，leaderboard 的可比性就建立在这一点上
（例：[SAVE, arXiv 2512.07730](https://arxiv.org/html/2512.07730v2) 的 Table 1，LLaVA-1.6 / LLaVA-NeXT / Qwen2-VL
与各 baseline 在同一套设置下报 CHAIR_S / CHAIR_I）。

**判断：按现状不合规，不能这样报。** 不是因为有意为之（这是断点续采按 key 跳过造成的意外），
而是因为这两个数**不属于同一套协议**：被问"Qwen 那格的生成预算是多少"时，诚实的回答是"两个"。
而且偏差是**单方向**的——配对测量显示延长预算只会增加幻觉、从不减少，所以偏短的那一半
系统性地让这一格显得更容易，方向恰好有利于"达标"这个结论。

**要合规，最低限度是重采**（把这一格的 1,200 条放在同一个预算下重跑）。
**更强的做法是补一张预算敏感性表**：三个模型都在两个（或三个）预算下各报一次。
当某个协议参数已知会动指标时，主流论文的应对就是把它显式测出来、证明结论不随它翻，
而不是把它固定成一个方便的值。对这份汇报而言，这张表同时也是对"预算是不是挑出来的"这一质疑的正面回答。

**一处需要澄清的文献说法。** 有一份技术报告称"生成描述的平均长度与幻觉率无明显相关"
（[EECS-2019-93](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2019/EECS-2019-93.pdf)）。
那说的是**跨模型比较平均长度**，与本例不同：这里是同一个模型、同一批条目、只换预算，
实测 +12.2 个百分点且单向。两者不矛盾，但不能用前者来反驳后者。
（该报告我只见到了检索摘要中的这一句，未逐字核对其设定。）

## 四、没有做的事（不能算数）

- 没有核对 COCO 标注文件本身与官方发布的同一性（只核了标签由它推出、且过程可复跑）。
- 没有核对 POPE / TextVQA 官方题库文件与官方发布版本的哈希。
- 没有对 CHAIR 做"同一张图在三个 setting 下的题是否重复计数"的独立判断（只核了 id 唯一、切分不泄漏）。
